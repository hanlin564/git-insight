# Git Insight 后续可做功能

本文记录对当前 Git Insight 工具现状的梳理，以及后续值得投入的功能方向。当前结论基于源码、README、测试文档和实际运行输出观察。

## 现状判断

Git Insight 已经具备单仓库提交活跃度分析的核心能力，包括：

- 当前或指定分支的提交统计。
- 提交热力图。
- 作者排行榜。
- 作者账号合并配置。
- `--me` 当前 Git 用户视角。
- 本地分支活跃和不活跃分组。
- 静态 HTML 报告输出。
- 中英文界面配置。

当前工具更偏展示型：能回答“最近谁提交多、仓库什么时候活跃、哪些本地分支较久未动”，但还不够擅长回答“风险集中在哪里、哪些维护动作最值得做、当前周期和上一周期相比有没有变化”。

## 高价值功能方向

### 1. 路径热点和文件热点分析（已完成）

这是最值得优先做的方向。当前只统计作者维度，缺少文件和目录维度。可以增加：

- 改动最多的目录。
- 改动最多的文件。
- 改动最多的文件类型。
- 高频改动且多作者参与的热点文件。

价值：帮助判断重构优先级、代码所有权、技术债集中区域和潜在风险文件。

当前已实现改动最多的文件、改动最多的文件类型，以及按不同作者人数排序的多作者热点文件分析。

### 2. 统计排除规则（已完成基础版）

当前 `changedLines = additions + deletions` 容易被锁文件、生成文件、构建产物、迁移脚本或格式化提交污染。建议在 `.git-insight.json` 中支持：

- `excludePatterns`

价值：提高排行榜和热点统计可信度，避免把无意义的大文件改动误判成真实代码贡献或风险。

当前已实现 `excludePatterns`，支持接近 `.gitignore` 的文件、目录和通配符写法，用于过滤统计口径，不影响 Git 跟踪状态。后续如有需要，再评估 `includePatterns` 或 `ignoreGenerated`。

### 3. 周期对比

当前报告只展示一个时间范围内的绝对值。可以增加当前周期和上一周期对比：

- 提交数变化。
- 活跃作者数变化。
- 改动行数变化。
- 活跃天数变化。
- 热点目录变化。

价值：让报告从“静态快照”变成“趋势分析”，更适合周报、月报和项目健康检查。

### 4. 分支治理增强

当前分支活跃度只看本地分支，且 90 天阈值固定。可以增强为：

- 支持 `--stale-days` 自定义阈值。
- 支持远程分支。
- 展示相对默认分支的 ahead/behind。
- 展示最后提交作者。
- 判断分支是否已合并到默认分支。

价值：让报告能直接辅助清理长期分支和发现需要处理的开发分支。

### 5. JSON 和 CSV 输出

HTML 适合阅读，但不适合集成。建议增加：

- `--json`
- `--csv`

价值：方便接入 CI、仪表盘、自动周报、飞书或 Slack 通知。

### 6. 多仓库扫描

README 中已提到后续结构预留多仓库扫描能力。可以增加：

- `--workspace <dir>` 扫描目录下所有 Git 仓库。
- 汇总每个仓库的最近提交时间。
- 汇总每个仓库的活跃作者数量。
- 汇总每个仓库的不活跃分支数量。
- 标记长期未维护仓库。

价值：从单仓库分析扩展到本地工作区或团队项目盘点。

### 7. 终端热力图自适应

实际运行 `--last 365` 时，终端热力图在较窄终端中容易折行。可以增加：

- 根据终端宽度自动切换紧凑模式。
- 提供 `--compact`。
- 提供 `--monthly` 强制月度视图。

价值：改善终端阅读体验，避免长时间范围输出变形。

## 建议优先级

建议按以下顺序推进：

1. [x] 路径热点和文件热点分析。
2. [x] 统计排除规则基础版。
3. 周期对比。
4. 分支治理增强。
5. JSON 和 CSV 输出。
6. 多仓库扫描。
7. 终端热力图自适应。

前两项优先解决统计可信度问题；第三和第四项提升报告的决策价值；第五和第六项扩展工具的集成和规模化使用场景；第七项主要改善终端体验。
