## 问题清单

### 1. 作者排名存在重复 key 警告

现象：

- 输出中出现 `Warning: Encountered two children with the same key, Ray-ux`。
- `Author Ranking by Commits` 和 `Author Ranking by Changed Lines` 中都出现多个 `Ray-ux` 条目。

初步原因：

- Erp 仓库存在同名不同邮箱的作者记录，例如：
  - `Ray-ux <59766459+Ray-ux@users.noreply.github.com>`
  - `Ray-ux <zlw20010124@163.com>`
- `BarChart` 当前使用展示标签作为 React key，同名作者会导致 key 冲突。

影响：

- 终端输出夹杂 React 警告，影响可读性。
- React 明确提示重复 key 行为不受支持，后续可能出现条目重复或遗漏。

建议：

- 为柱状图条目补充稳定唯一 key，避免直接使用展示标签。
- 作者排名场景可以使用作者身份 key 或邮箱参与生成 key。

### 2. 3650 天热力图超宽且不可读

现象：

- `--since 3650` 会输出约 10 年的日期热力图。
- 月份标签和每日方块在终端中大量换行，布局失控。
- 实际输出难以看出提交密度和时间分布。

初步原因：

- 热力图按 `--since` 生成完整日期范围。
- 3650 天约等于 522 周，当前 UI 直接横向渲染所有周列。

影响：

- 长时间范围下热力图基本不可用。
- 大量输出淹没后续作者排名和分支活跃度信息。

建议：

- 对热力图设置最大展示跨度，例如默认最多展示最近 365 天。
- 或增加独立参数控制热力图范围，避免和作者统计范围强绑定。
- 也可以在终端宽度不足时降级为摘要统计。

### 3. 热力图展示范围和标题语义不够清晰

现象：

- `Author Contribution Heatmaps` 使用复数标题。
- Erp 测试中实际只展示当前 Git 用户 `Hanlin Wang <1438322563@qq.com>` 的热力图。
- 作者排名展示所有作者，热力图只展示当前用户，两者范围不一致。

初步原因：

- 当前热力图逻辑依赖仓库中的 `git config user.name` 和 `git config user.email`。
- 没有在界面上说明热力图默认只针对当前 Git 用户。

影响：

- 用户可能误以为热力图会展示所有作者。
- 对多作者仓库进行分析时，输出语义容易产生误解。

建议：

- 在热力图区块标题或说明中明确“当前 Git 用户”。
- 或提供参数允许展示指定作者、全部作者或排名前 N 作者的热力图。

### 4. 无近期提交时分支活跃度输出 0 值分支

现象：

- `--since 90` 输出“当前统计范围内没有匹配的提交数据”。
- `Branch Activity` 仍显示：
  - `WangHanlin 0`
  - `master 0`

初步原因：

- 分支活跃度统计会列出本地分支，即使统计范围内提交数为 0。

影响：

- 对老仓库或长期无提交仓库，0 值分支信息价值较低。
- 和“没有匹配提交数据”的提示放在一起时显得噪声较大。

建议：

- 当所有分支提交数都为 0 时，显示“当前分支统计范围内暂无活跃分支”。
- 或默认隐藏 0 值分支，必要时通过参数展示。
